### 01. Interfejsy ABC i Protocol

- [ABC czy Protocol](01%20Interfejsy%20ABC%20i%20Protocol.md#abc-czy-protocol): [abc — Abstract Base Classes](https://docs.python.org/3/library/abc.html). Klasa z metaklasą ABCMeta nie może być instancjonowana, dopóki wszystkie metody abstrakcyjne nie zostaną nadpisane; TypeError pojawia się przy tworzeniu instancji.
- [ABC czy Protocol](01%20Interfejsy%20ABC%20i%20Protocol.md#abc-czy-protocol): [typing — Support for type hints (Protocol)](https://docs.python.org/3/library/typing.html). Protocol jest sprawdzany przez statyczne type checkery (structural subtyping); klasa nie musi dziedziczyć po Protocol, by pasować (przykład Proto/C).
- [Składanie zamiast dziedziczenia](01%20Interfejsy%20ABC%20i%20Protocol.md#składanie-zamiast-dziedziczenia): [typing — Support for type hints (Protocol)](https://docs.python.org/3/library/typing.html). Klasa nie musi dziedziczyć po Protocol, by pasować do niego strukturalnie (statyczne duck-typing); KalendarzObcy bez dziedziczenia po Kalendarz pasuje, jeśli ma zgodną metodę poniedzialki.
- [Struktura pakietu i pierwszy test](01%20Interfejsy%20ABC%20i%20Protocol.md#struktura-pakietu-i-pierwszy-test): [pytest: Configuration (customize)](https://docs.pytest.org/en/stable/reference/customize.html). Sekcja [tool.pytest.ini_options] dla pytest 8.x, natywne [tool.pytest] od 9.0; listy w TOML.
- [Struktura pakietu i pierwszy test](01%20Interfejsy%20ABC%20i%20Protocol.md#struktura-pakietu-i-pierwszy-test): [pytest: API Reference (confval pythonpath)](https://docs.pytest.org/en/stable/reference/reference.html#confval-pythonpath). pythonpath dodaje katalogi do sys.path na czas testów (bez instalowania pakietu); domyślne python_files i python_functions.
- [Atrapa z podglądem wywołań](01%20Interfejsy%20ABC%20i%20Protocol.md#atrapa-z-podglądem-wywołań): [unittest.mock — mock object library (Python 3.13)](https://docs.python.org/3.13/library/unittest.mock.html). Mock(spec=Klasa) rzuca AttributeError dla nieistniejących atrybutów; return_value ustawiane na metodzie-dziecku; assert_called_once_with sprawdza dokładnie jedno wywołanie z podanymi argumentami.
- [Uruchamianie pytest w terminalu](01%20Interfejsy%20ABC%20i%20Protocol.md#uruchamianie-pytest-w-terminalu): [pytest API Reference (confval pythonpath, python_files)](https://docs.pytest.org/en/stable/reference/reference.html#confval-pythonpath). pythonpath w [tool.pytest.ini_options] dodaje katalogi do sys.path względem rootdir, więc pythonpath = ["."] pozwala importować urzad; domyślne python_files to test_*.py i *_test.py.
- [Uruchamianie pytest w terminalu](01%20Interfejsy%20ABC%20i%20Protocol.md#uruchamianie-pytest-w-terminalu): [pytest: Import mechanisms and sys.path](https://docs.pytest.org/en/stable/explanation/pythonpath.html). Tryb prepend (domyślny) wstawia do sys.path katalog modułu testowego (tests/), a nie katalog główny projektu, więc pythonpath jest potrzebne.

### 02. Model domeny wniosku

- [Test przez interfejs, nie implementację](02%20Model%20domeny%20wniosku.md#test-przez-interfejs-nie-implementację): [unittest.mock — mock object library](https://docs.python.org/3/library/unittest.mock.html). Mock.assert_called_once_with(*args, **kwargs) sprawdza, że mock wywołano dokładnie raz i z podanymi argumentami.
- [Test przez interfejs, nie implementację](02%20Model%20domeny%20wniosku.md#test-przez-interfejs-nie-implementację): [How to parametrize fixtures and test functions](https://docs.pytest.org/en/stable/how-to/parametrize.html). @pytest.mark.parametrize uruchamia test wielokrotnie z różnymi zestawami argumentów, więc można go użyć do testu po kilku implementacjach kontraktu.
- [Model wniosku jako dataclass](02%20Model%20domeny%20wniosku.md#model-wniosku-jako-dataclass): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). Potwierdza: @dataclass generuje __init__, __repr__, __eq__; frozen=True powoduje FrozenInstanceError przy przypisaniu; eq=True i frozen=False ustawia __hash__ na None, a eq=True i frozen=True generuje __hash__; frozen działa płytko (lista w zamrożonej klasie nadal się zmienia).
- [Pieczątka z przyszłości](02%20Model%20domeny%20wniosku.md#pieczątka-z-przyszłości): [dataclasses — Data Classes](https://docs.python.org/3/library/dataclasses.html). @dataclass(frozen=True) z jednym polem i własną metodą działa; frozen blokuje tylko przypisanie i usuwanie pól (FrozenInstanceError), a __post_init__ jest wołany z wygenerowanego __init__, więc twierdzenie o możliwym miejscu reguły jest poprawne.
- [Pieczątka z przyszłości](02%20Model%20domeny%20wniosku.md#pieczątka-z-przyszłości): [How to write and report assertions in tests (pytest 8.3)](https://docs.pytest.org/en/8.3.x/how-to/assert.html). pytest.raises(KlasaWyjątku) jako menedżer kontekstu działa tak, jak opisano w sekcji; brak wyjątku w teście dla Pieczatka(2024) wystarczy sprawdzić zwykłym wywołaniem.
- [Załącznik z obcego kalendarza](02%20Model%20domeny%20wniosku.md#załącznik-z-obcego-kalendarza): [datetime — Basic date and time types (Python 3.13)](https://docs.python.org/3.13/library/datetime.html). datetime.strptime(date_string, format) zwraca datetime; %Y, %m, %d to rok z wiekiem, miesiąc i dzień; .date() zwraca date, więc FORMATY i jako_date() działają. Daty w wyniku (2024-03-04 i 2024-04-03) wynikają z tych dyrektyw.
- [Załącznik z obcego kalendarza](02%20Model%20domeny%20wniosku.md#załącznik-z-obcego-kalendarza): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). @dataclass(frozen=True) emuluje niezmienność (FrozenInstanceError przy przypisaniu), a kolejność pól w __init__ to kolejność w klasie, więc Zalacznik("a.ics", "us", "03/04/2024") jest poprawne.
- [Zdarzenia w życiu wniosku](02%20Model%20domeny%20wniosku.md#zdarzenia-w-życiu-wniosku): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). @dataclass(frozen=True) blokuje modyfikację pól (FrozenInstanceError), eq=True domyślnie generuje porównanie po zawartości pól, a eq=True z frozen=True generuje __hash__; to potwierdza opis zdarzenia jako niezmiennej wartości porównywanej po zawartości.
- [Głos i decyzja komisji](02%20Model%20domeny%20wniosku.md#głos-i-decyzja-komisji): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). frozen=True daje tylko płytką niezmienność (lista w polu nadal się zmienia, ale przypisanie pola zgłasza FrozenInstanceError), a property w zamrożonym dataclasie działa. To potwierdza uzasadnienie użycia tuple zamiast list i kod klasy Decyzja.

### 03. Tworzenie wniosków

- [Builder składa wniosek](03%20Tworzenie%20wniosk%C3%B3w.md#builder-składa-wniosek): [typing — Support for type hints (Python 3.13)](https://docs.python.org/3.13/library/typing.html). Self jest importowalne z typing, dodane w 3.11, służy do adnotowania metod zwracających self przy łańcuchowaniu.
- [Prototype klonuje wniosek](03%20Tworzenie%20wniosk%C3%B3w.md#prototype-klonuje-wniosek): [copy — Shallow and deep copy operations](https://docs.python.org/3/library/copy.html). copy.copy tworzy płytką kopię, copy.deepcopy rekurencyjną. copy.replace istnieje od 3.13 i obsługuje dataclasses przez __replace__.
- [Singleton jako konfiguracja urzędu](03%20Tworzenie%20wniosk%C3%B3w.md#singleton-jako-konfiguracja-urzędu): [functools — Higher-order functions (Python 3.13)](https://docs.python.org/3.13/library/functools.html). `cache` zwraca to samo co `lru_cache(maxsize=None)`, a opakowanie ma `cache_clear()`. Cache jest wątkowo bezpieczny, ale funkcja może zostać wywołana więcej niż raz przy równoległych wywołaniach.
- [Singleton jako konfiguracja urzędu](03%20Tworzenie%20wniosk%C3%B3w.md#singleton-jako-konfiguracja-urzędu): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). `frozen=True` blokuje przypisania przez `FrozenInstanceError`. Przy `eq=True` generowany jest `__hash__`, a repr ma postać `Konfiguracja(rok_biezacy=2024, ...)`. Zamrożenie jest płytkie.
- [Singleton jako konfiguracja urzędu](03%20Tworzenie%20wniosk%C3%B3w.md#singleton-jako-konfiguracja-urzędu): [pytest fixtures (8.3)](https://docs.pytest.org/en/8.3.x/how-to/fixtures.html). `autouse=True` uruchamia fixture przy każdym teście. Kod przed `yield` to setup, a po `yield` to teardown, przy domyślnym zakresie function.
- [Od danych do kompletnego wniosku](03%20Tworzenie%20wniosk%C3%B3w.md#od-danych-do-kompletnego-wniosku): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). dataclasses.replace(wzor, numer=2) działa na zamrożonych dataclassach, tworzy obiekt przez __init__() (wywołuje __post_init__()), nie kopiuje pól init=False, a podanie takiego pola w changes zgłasza ValueError.
- [Adapter obcego kalendarza](03%20Tworzenie%20wniosk%C3%B3w.md#adapter-obcego-kalendarza): [datetime — Basic date and time types (Python 3.13)](https://docs.python.org/3.13/library/datetime.html). date.fromisoformat przyjmuje napisy ISO 'YYYY-MM-DD' (w 3.11+ także inne formaty ISO 8601), więc `date.fromisoformat(n)` w adapterze działa; konwencja 0 = poniedziałek jest zgodna z date.weekday().
- [Composite i teczka wniosków](03%20Tworzenie%20wniosk%C3%B3w.md#composite-i-teczka-wniosków): [typing — Support for type hints (Python 3.13)](https://docs.python.org/3.13/library/typing.html). Protocol umożliwia strukturalne typowanie (static duck-typing): klasa spełnia Protocol bez dziedziczenia po nim, co potwierdza twierdzenie, że Wniosek nie musi po niczym dziedziczyć.

### 04. Struktury wniosku

- [Flyweight i pula pieczątek](04%20Struktury%20wniosku.md#flyweight-i-pula-pieczątek): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). frozen=True dodaje __setattr__ i __delattr__ rzucające FrozenInstanceError, więc pól nie da się zmienić po utworzeniu. Przy eq=True (domyślnie) i frozen=True powstaje też __hash__, więc Pieczatka nadaje się na wartość współdzieloną.
- [Flyweight i pula pieczątek](04%20Struktury%20wniosku.md#flyweight-i-pula-pieczątek): [functools — Higher-order functions (Python 3.13)](https://docs.python.org/3.13/library/functools.html). @cache jest dostępny bez nawiasów od Pythona 3.9 i działa jak lru_cache(maxsize=None). Argumenty muszą być hashowalne, więc rok: int jako klucz jest poprawny. Nie sprawdziłem wprost, że @cache ma cache_clear(), ale sekcja tego nie twierdzi.
- [Interpreter reguł komisji](04%20Struktury%20wniosku.md#interpreter-reguł-komisji): [typing — Support for type hints (Python 3.13)](https://docs.python.org/3.13/library/typing.html). Protocol wspiera podtypowanie strukturalne, klasa implementująca nie musi po niczym dziedziczyć, więc twierdzenie „nowy węzeł nie dziedziczy po niczym” jest zgodne z dokumentacją.
- [Interpreter reguł komisji](04%20Struktury%20wniosku.md#interpreter-reguł-komisji): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). @dataclass(frozen=True) blokuje zmianę pól (FrozenInstanceError), więc Wiekszosc jest niezmienna, a przy eq=True dostaje też __hash__, co pasuje do współdzielenia drzewa.
- [Iterator po teczce](04%20Struktury%20wniosku.md#iterator-po-teczce): [Python reference: Expressions (yield expressions, generator-iterator methods)](https://docs.python.org/3/reference/expressions.html). `yield from` deleguje do poditeratora, a generator jest iteratorem i jest jednorazowy. Potwierdza to sens `yield from skladnik` w `__iter__` i uwagę o drugim przebiegu.

### 05. Przepływ komisji

- [Memento jako migawka wniosku](05%20Przep%C5%82yw%20komisji.md#memento-jako-migawka-wniosku): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). field(repr=False) wyłącza pole z __repr__, więc print(migawka) daje Migawka(). frozen=True blokuje tylko przypisanie pól, więc zamrożenie jest płytkie i wewnętrzny dict nadal można zmienić.
- [Memento jako migawka wniosku](05%20Przep%C5%82yw%20komisji.md#memento-jako-migawka-wniosku): [Built-in Functions: vars (Python 3.13)](https://docs.python.org/3.13/library/functions.html). vars(obj) zwraca modyfikowalny __dict__ instancji, więc vars(self).update(...) przywraca atrybuty. Bez __dict__ (np. __slots__) rzuca TypeError.
- [Observer i subskrybenci zdarzeń](05%20Przep%C5%82yw%20komisji.md#observer-i-subskrybenci-zdarzeń): [weakref — Weak references (Python 3.13)](https://docs.python.org/3.13/library/weakref.html). WeakMethod(method) symuluje słabą referencję do metody związanej, bo zwykłe słabe referencje nie utrzymują efemerycznych metod związanych. Żywy WeakMethod wywołany zwraca metodę, a martwy zwraca None. Dla zwykłych funkcji służy weakref.ref.
- [Visitor i raporty po teczkach](05%20Przep%C5%82yw%20komisji.md#visitor-i-raporty-po-teczkach): [functools — Higher-order functions and operations on callable objects (Python 3.13)](https://docs.python.org/3.13/library/functools.html). functools.singledispatch wybiera implementację funkcji po typie pierwszego argumentu, co potwierdza zdanie o singledispatch w sekcji.

### 06. System Urzędu Zaginionych Poniedziałków

- [Decyzja z powiadomieniami i cofaniem](06%20System%20Urz%C4%99du%20Zaginionych%20Poniedzia%C5%82k%C3%B3w.md#decyzja-z-powiadomieniami-i-cofaniem): [Python 3.13 Language Reference: Compound statements (class patterns)](https://docs.python.org/3.13/reference/compound_stmts.html#class-patterns). Wzorce klasowe ze słowami kluczowymi (DecyzjaPodjeta(numer=n, przyznana=p)) szukają atrybutów przez getattr i działają z dataclass, w tym frozen. Brak dopasowania bez `_` nie zgłasza błędu, tylko pomija match.
- [Wszystkie wzorce w jednym przepływie](06%20System%20Urz%C4%99du%20Zaginionych%20Poniedzia%C5%82k%C3%B3w.md#wszystkie-wzorce-w-jednym-przepływie): [functools — Higher-order functions (Python 3.13)](https://docs.python.org/3.13/library/functools.html). `@cache` istnieje od Pythona 3.9 i działa jako dekorator funkcji, także bez argumentów. To potwierdza wiersz tabeli „Singleton | `@cache` na funkcji”.
- [Wszystkie wzorce w jednym przepływie](06%20System%20Urz%C4%99du%20Zaginionych%20Poniedzia%C5%82k%C3%B3w.md#wszystkie-wzorce-w-jednym-przepływie): [dataclasses — Data Classes (Python 3.13)](https://docs.python.org/3.13/library/dataclasses.html). `dataclasses.replace(obj, /, **changes)` tworzy nowy obiekt tego samego typu z podmienionymi polami. To potwierdza wiersz „Prototype | `dataclasses.replace`”.
