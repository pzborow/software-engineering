# EC2 — Elastic Compute Cloud

**Opis**
Wynajmujesz wirtualny serwer (VM) z pełnym dostępem root. Wchodzisz na niego SSH-em i robisz wszystko, co na zwykłej maszynie.

**Kluczowe koncepty**
- **Instance** — wirtualny serwer; wybierasz **typ** (t3.micro, GPU, memory-heavy...) i obraz (AMI).
- **Region / Availability Zone** — region to miejsce na mapie, AZ to niezależne data center w regionie; rozrzucaj instancje między AZ.
- **Security Group** — firewall: które porty i skąd są otwarte.
- **Auto Scaling** — automatyczne dokładanie/odjemanie instancji pod obciążenie.
- **Load Balancer** — jeden adres przed wieloma instancjami, rozkłada ruch.

**Key points**
- Wybór **typu instancji**: ogólnego przeznaczenia, CPU-heavy, memory-heavy, GPU itd.
- Instancje żyją w **regionach** i **strefach dostępności** (niezależne data center) — rozrzucaj je dla niezawodności.
- **Auto Scaling**: automatyczne dokładanie/odjemanie instancji pod obciążenie.
- **Elastic Load Balancer**: jeden punkt wejścia przed wieloma instancjami, rozkłada ruch.

**Example (AWS CLI)**
```bash
# stworzenie security group z otwartym SSH i HTTP
aws ec2 create-security-group --group-name app-sg --description "app"
aws ec2 authorize-security-group-ingress --group-name app-sg \
  --ip-permissions \
    "IpProtocol=tcp,FromPort=22,ToPort=22,IpRanges=[{CidrIp=0.0.0.0/0}]" \
    "IpProtocol=tcp,FromPort=80,ToPort=80,IpRanges=[{CidrIp=0.0.0.0/0}]"

# uruchomienie instancji
aws ec2 run-instances --image-id ami-0abc123 --instance-type t3.micro \
  --security-group-ids sg-0abc --count 2 --tag-specifications \
  'ResourceType=instance,Tags=[{Key=Name,Value=app}]'

# podgląd
aws ec2 describe-instances \
  --query 'Reservations[*].Instances[*].[InstanceId,State.Name,PublicIpAddress]'
ssh ec2-user@<public-ip>

# koniec — instancja (i jej dysk) znika
aws ec2 terminate-instances --instance-ids i-0abc123
```

Auto Scaling:
```bash
# grupa skalująca: 2–4 instancje
aws autoscaling create-auto-scaling-group \
  --auto-scaling-group-name app-asg --min-size 2 --max-size 4 \
  --launch-template LaunchTemplateId=lt-0abc,Version=1 \
  --target-group-arns arn:aws:elasticloadbalancing:...:targetgroup/app/tg-0abc \
  --availability-zones us-east-1a us-east-1b

aws autoscaling update-auto-scaling-group --auto-scaling-group-name app-asg --max-size 8
```

**Pełny flow** — od zera do serwera z aplikacją:
```bash
# 1. security group: otwórz SSH (22) i HTTP (80)
aws ec2 create-security-group --group-name app-sg --description "app"
aws ec2 authorize-security-group-ingress --group-name app-sg \
  --ip-permissions "IpProtocol=tcp,FromPort=22,ToPort=22,IpRanges=[{CidrIp=0.0.0.0/0}]" \
  "IpProtocol=tcp,FromPort=80,ToPort=80,IpRanges=[{CidrIp=0.0.0.0/0}]"

# 2. utwórz key pair (klucz do SSH) — jeśli nie masz
aws ec2 create-key-pair --key-name mykey --query KeyMaterial > mykey.pem
chmod 400 mykey.pem

# 3. uruchom instancję (Amazon Linux 2, t3.micro)
aws ec2 run-instances --image-id ami-0abc123 --instance-type t3.micro \
  --security-group-ids sg-0abc --key-name mykey \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=app}]'

# 4. odczytaj publiczny IP
aws ec2 describe-instances \
  --query 'Reservations[0].Instances[0].PublicIpAddress'
# -> "34.1.2.3"

# 5. wejdź SSH-em i zainstaluj aplikację
ssh -i mykey.pem ec2-user@34.1.2.3
# na serwerze:
sudo dnf install -y python3
python3 /home/ec2-user/app.py &
# wyjdź: exit

# 6. zweryfikuj, że działa
curl http://34.1.2.3/

# 7. koniec — zatrzymaj (tańsze) albo zakończ (kasuje dysk)
aws ec2 stop-instances --instance-ids i-0abc123
aws ec2 terminate-instances --instance-ids i-0abc123
```
